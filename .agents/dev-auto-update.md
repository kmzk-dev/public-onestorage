# ONE STORAGE: 管理画面からの直接ZIPアップデート機能 実装指示プロンプト

## 目的・背景

ONE STORAGEのバージョン更新を、`installer.php` や FTP を介さず、管理画面（`admin.php`）から直接GitHubのリリースZIPをダウンロード・上書き展開して完結させる「セルフアップデータ機能」を実装してください。

`installer.php` で実証済みの「ダウンロード・解凍・データ保護上書き」のロジックをバックエンドAPIに移植し、安全かつ段階的なバージョンアップを可能にします。

## 前提条件・制約事項（最重要）

1. **データおよび設定の完全保護（上書き禁止リスト）:**
   ZIP展開時、以下のファイルおよびディレクトリは**絶対に上書き・削除してはならない**（`installer.php` の `recursive_copy` と同等のガードを徹底すること）。
   * `config/` ディレクトリ配下の全ファイル（`auth.php`, `config.php`, `cookie_key.php`, `mfa_secret.php`, `accept.json`, `share_config.php` 等）
   * 実データ領域: `data*`（`data[A-Za-z0-9]{10,}` 等の難読化フォルダ）
   * 共有領域: `share*`（`share[A-Za-z0-9]{10,}` 等のフォルダ）
   * データベース実体: `.storage.db`, `.share.db`
   * 一時キャッシュやインストーラー残骸: `.installer_done`, `installer.php`

2. **タイムアウト対策と処理中断の防止（不整合事故の防止）:**
   * レンタルサーバーの `max_execution_time` 制限による「ファイル上書き途中の強制終了（画面のホワイトアウト）」を絶対に防ぐこと。
   * アップデート処理実行時は必ず `@set_time_limit(120);` および `ignore_user_abort(true);` を冒頭で宣言すること。
   * ZIPを直接ルートに解凍するのではなく、**必ず一時ディレクトリ（`sys_get_temp_dir()`）へ完全に展開・検証した上で、コピー処理を一気に完走させること**。

3. **将来のデータベース（SQLite）変更への配慮:**
   * ファイル更新に伴い、新バージョンでテーブルやカラムの追加が行われるケースを想定すること。
   * アップデート適用後の初回アクセス（リロード時）に、既存のDB接続・初期化ロジック（`get_db()` / `init_db_schema()` 等）経由で `CREATE TABLE IF NOT EXISTS` や必要なスキーマ追記が安全に走る構造を崩さないこと。
   * 既存のSQLite実体（`.storage.db`, `.share.db`）を初期化・削除するような破壊的処理は一切含めないこと。

4. **GitHub API の手動トリガー（リクエスト削減）:**
   * 管理画面アクセス時に自動でGitHub APIを叩かないこと（IP制限・60回/時 を回避するため）。
   * ユーザーが「アップデートを確認」ボタンをクリックした時のみ API をフェッチすること。

5. **段階的アップデート（バージョン選択）の提供:**
   * GitHub Releases API からリリース一覧を取得し、**現在の `APP_VERSION` より新しいバージョンのみ**をセレクトボックスに抽出・表示すること。
   * ユーザーは最新（latest）だけでなく、任意のバージョンを選択して更新できること。

## 改修・追加対象ファイル

1. `functions/admin_api.php`（バックエンドAPIの追加）
2. `admin.php`（フロントエンドUIおよび更新処理スクリプトの追加）
3. `path.php`（定数定義の確認）

## 実装要件

### 1. `functions/admin_api.php` への追加

以下の2つのアクション（エンドポイント）を追加してください。既存の認証チェック（`check_authentication()`）が有効であることを前提とします。

#### ① `action: 'check_releases'`
* **処理内容:**
  * GitHub API (`https://api.github.com/repos/kmzk-dev/onestorage/releases`) から直近のリリース一覧（JSON）を取得。
  * 現在のバージョン定数 `APP_VERSION`（未定義時は '1.0.0'）と比較し、**現在のバージョンより新しいリリースのみ**をフィルタリング。
  * レスポンスとして各リリースの `tag_name`, `name`, `published_at`, `zip_url`（`zipball_url` または assets内の `.zip`）を配列で返却する。
  * 新しいバージョンが存在しない場合は `has_update: false` を返す。

#### ② `action: 'apply_update'`
* **入力:** `version`（対象タグ名）または `zip_url`
* **処理内容:**
  1. 冒頭で `@set_time_limit(120);` および `ignore_user_abort(true);` を実行。
  2. `installer.php` の `download_zip()` のロジックを用いて、ZIPファイルをサーバーの一時ディレクトリ（`sys_get_temp_dir()`）へストリームダウンロード（リダイレクト追跡、タイムアウト設定必須）。
  3. `ZipArchive` で一時フォルダへ展開。
  4. `find_source_root()` でZIP内のソースルートを特定。
  5. `recursive_copy()` を用い、**保護対象（config, data*, share*, .storage.db, .share.db 等）を除外しながら、Web公開ルート（`__DIR__ . '/..'`）へファイルを上書きコピーする。
  6. コピー完了後、一時ディレクトリ・一時ZIPを削除。
  7. 成功時は `{ success: true, message: 'アップデートが完了しました。ページを再読み込みします。' }` を返却する。
  8. 処理中のエラー（権限不足、ZIP破損、展開失敗等）は適切にキャッチして失敗レスポンスを返すこと。

### 2. `admin.php`（管理画面）UI & JSの実装

現在ある `section-version`（バージョン情報セクション）を改修します。

#### UI仕様:
1. **初期状態:**
   * 現在のバージョンバッジ（例: `v1.1.0`）を表示。
   * `[アップデートを確認]` ボタンを配置。
2. **確認後（更新あり）:**
   * 「新しいバージョンが利用可能です」と表示。
   * バージョン選択用プルダウン `<select>` を表示（最新版に `selected` を付与）。
   * 各バージョンのリリースノートへの外部リンク、または公開日を補足表示。
   * `[このバージョンにアップデート]` ボタンを表示。
   * クリック時に「アップデートを実行しますか？必要に応じて事前にバックアップを取得してください。」のブラウザ確認ダイアログ（`confirm`）を挟む。
3. **確認後（最新状態）:**
   * 「お使いの ONE STORAGE は最新です」という緑のバッジまたはアラートを表示。
4. **アップデート実行中:**
   * ボタンをスピナー表示（無効化）にし、「ダウンロード中... 展開中...」などのプログレス表示を行う。
5. **完了後:**
   * トースト通知または完了アラートを表示し、1.5〜2秒後に `window.location.reload()` で画面をリロード（新バージョンの画面へ自動更新）。

## 完了条件

* [ ] 管理画面から「アップデートを確認」を押すと、GitHub Releases API から正しく新バージョン一覧が取得できること。
* [ ] 実行時にタイムアウト対策（`set_time_limit` / `ignore_user_abort`）が適用され、安全に一括コピーされること。
* [ ] バージョンを選択して実行した際、既存の `config/`、`data*`、`share*`、`.storage.db` の中身が**100%保護されたまま**、本体コードのみが上書きされること。
* [ ] アップデート完了後の自動リロードで、`admin.php` のバージョン表示が選択した新バージョンに更新されること。
* [ ] セッションが維持され、再ログインを求められることなく管理画面がそのまま利用できること。
