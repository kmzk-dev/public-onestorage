# ONE STORAGE - セキュリティガイド (SECURITY)

ONE STORAGE におけるセキュリティモデルおよび安全な運用のためのガイドラインについて解説します。

---

## 1. セキュリティ設計思想

ONE STORAGE は、**「クラウド事業者のAI自動監査や外部検閲からプライベートなデータを守ること」** と **「低スペックなレンタルサーバー環境でも軽快かつ安全に稼働すること」** を最優先に設計されています。

### 防御の対象（何から守るか）
- **外部検閲・AIスキャン:** クラウドストレージやレンタルサーバー事業者の自動解析からプライベートな写真・文書・創作物を保護します。
- **第三者による直接ファイル窃取:** サーバーの公開領域やバックアップから物理ファイルを持ち出されても、暗号化により中身を解読させません。
- **不正アクセス・総当たり攻撃:** 強固な二要素認証（MFA）とHMAC署名付き認証機構により、管理画面への侵入を防ぎます。
- **内部ロジックへの直接呼び出し:** 実行コンテキスト制御（`ONESTORAGE_RUNNING`）により、エントリポイントを介さない悪意あるPHPスクリプト直接実行を遮断します。

### 限界事項（サーバー侵入時の考え方）
サーバー自体がroot権限やWebサーバー権限レベルでクラック・改ざんされた場合、プログラムコードや環境メモリそのものが攻撃者の支配下に置かれます。これはあらゆるWebアプリケーション共通の根本的な制約です。
そのため、ONE STORAGE では「侵入された後」ではなく、**「侵入させない入口対策」** と **「データ自体の常時暗号化」** に注力しています。

## 2. ファイル暗号化アーキテクチャ

ONE STORAGE のファイル暗号化は、以下の仕組みで動作します。

```text
[アップロード]
ブラウザ (チャンク分割) ──> サーバー一時領域 ──> ストリーム結合 ──> [AES-256-CBC 暗号化] ──> 保存 (.enc)
                                                                    ▲
                                                  管理者メールアドレスから派生した暗号鍵

[ダウンロード / プレビュー]
保存ファイル (.enc) ──> [ストリーム復号] ──> ブラウザへ直接ストリーミング出力
```

1. **AES-256-CBC ストリーム暗号化:**
   - ファイル保存時に 16 バイトの暗号論的擬似乱数 IV（初期化ベクトル）を生成し、ファイル先頭に付与した上で AES-256-CBC で暗号化します。
   - 大容量ファイルも一定のバッファサイズ（64KB単位）でストリーム処理されるため、サーバーのメモリ枯渇（`memory_limit` 超過）を起こしません。
2. **管理者メールアドレスに基づく鍵派生:**
   - 初期設定時に登録した **管理者メールアドレス** をシードとして暗号鍵を生成します。
   - これにより、サーバーが完全クラッシュ・停止した場合でも、メールアドレスさえ覚えていれば手元の復号ツールでファイルを 100% 復元できます。

## 3. 多層防御システム (Defense in Depth)

単一の対策に依存せず、複数の防御層を設けています。

| 防御層 | 対策内容 | 実装ファイル・箇所 |
| :--- | :--- | :--- |
| **二要素認証 (MFA / TOTP)** | Google Authenticator 等によるワンタイムパスワード認証（RFC 6238 準拠） | `functions/mfa.php`, `mfa_login.php` |
| **HMAC 署名付き認証 Cookie** | ログインセッションをランダムソルトを用いた HMAC-SHA256 で署名・検証。Cookie 改ざんやセッションハイジャックを防止 | `functions/cookie.php`, `functions/auth.php` |
| **二重アクセス遮断** | データディレクトリおよび `config/` ディレクトリに対し、`.htaccess` によるアクセス拒否 + 自動配置された `index.html` による多重防壁 | 各ディレクトリ直下 |
| **実行コンテキスト制御** | `ONESTORAGE_RUNNING` 定数が未定義の直接スクリプト実行を `die()` で即時拒否 | `functions/` 配下の全ロジック |
| **ランダムデータフォルダ名** | 初回セットアップ時に推測困難な 15 文字のランダムフォルダ名を生成 | `setting.php`, `config/config.php` |
| **セキュリティ自己診断** | 管理画面（`admin.php`）から `.htaccess` の有効性やディレクトリ保護状態をワンクリックで診断 | `functions/admin_api.php` |

## 4. 保存データのガイドライン

プライバシー保護とセルフホスティングを最大限に活かすためのデータ分類です。

### ✅ 保存に適しているデータ（推奨）
- 個人の写真、ホームビデオ、音声録音、PDF 書籍・資料
- 私的な創作物、デザインデータ、原稿、アイデアメモ、日記
- クラウドの AI 監査・誤検閲から完全に隔離したいプライベートデータ
- 手元 PC のバックアップとして一時保管したい大容量アーカイブ

### ❌ 保存を避けるべきデータ（非推奨）
- 銀行口座、クレジットカード番号、暗号資産の秘密鍵
- 各種 Web サービスや社内システムの生 ID / パスワード一覧
- 万が一の漏洩時に多大な金銭的・法的な損害・補償が発生する重要機密契約書

## 5. 万が一のデータ復旧保証

本リポジトリの [`decrypt_tool/`](decrypt_tool/) に同梱されているツールを利用することで、ローカル PC 上でファイルを安全に一括復号できます。

- **Web ブラウザ版 (`decrypt_tool/decrypt.html`):** ブラウザ上で単一ファイルを復号（外部通信なし・Web Crypto API）
- **Windows アプリ版 (`decrypt_tool/decrypt.zip`):** フォルダ内の全暗号化ファイルを一括復号（`decrypt.exe`）
- **Python スクリプト版 (`decrypt_tool/decrypt.py`):** クロスプラットフォーム対応のコマンドライン一括復号

詳しい使い方は [README-decrypted.md](README-decrypted.md) を参照してください。
